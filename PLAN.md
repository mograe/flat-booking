## Решения

- Популярные команды обслуживаются одним процессом long polling. Черновики диалогов хранятся в FSM.
- Интервалы полуоткрытые. Горизонт включает текущий день и указанное число следующих календарных дней.
- SQLite хранит UTC, локальная дата определяется по часовому поясу студии.
- Источник истины для напоминаний — база данных. Изменение брони и её напоминаний выполняется одной транзакцией.
- Очередь уведомлений и завершившиеся бронирования проверяются отдельными задачами каждые 30 и 60 секунд соответственно. Интервалы настраиваются через окружение. Каждая задача выполняется в одном экземпляре в процессе, а при отсутствии изменений обращается к SQLite только на чтение.
- После задержки или перезапуска напоминание остаётся доступным к отправке до начала бронирования. Сетевой запрос выполняется вне транзакции SQLite. Уже записанный статус доставки защищает от повторной отправки при следующем проходе.
- Журнал содержит бизнес-события и безопасный контекст ошибок. SQL отключён по умолчанию и включается через `SQL_ECHO` со скрытыми значениями параметров.
- Белый список использует существующие учётные записи. Дата включения и комментарий хранятся в профиле. Однократный импорт окружения отмечается в SQLite. Отзыв доступа сохраняет историю и оставляет предстоящие бронирования доступными для отдельной отмены.
- Ревизия `4c8e2e115f39` переносит участников и повышает сохранённый стандартный максимум с 240 до 1440 минут. Другие настроенные значения сохраняются. Создание и перенос проверяют полный интервал, а расписание показывает его по местным суткам.

## Итоговая проверка

- Белый список и бронирования до 24 часов проверены полным прогоном из 80 тестов на Python 3.12.16. Проверены старые callback-кнопки после удаления, однократный импорт, миграция базы с существующим бронированием, сохранение пользовательского лимита, границы дней и конкурентная запись через независимые подключения. Ruff прошёл. На временной SQLite-базе Alembic подтвердил ревизию `4c8e2e115f39` и соответствие моделей схеме.
- После оптимизации на Python 3.12.16 прошли 47 тестов. Проверены пустые проходы планировщика, доставка после задержки и перезапуска, ограничение Telegram, конкурентная запись через независимые подключения SQLite и журналирование со скрытыми данными. Ruff и `alembic check` на новой временной базе прошли.
- Первоначальный прогон включал 31 тест на Python 3.12.16 и 3.13.16. Диалоги и запуск проверены с подменой Telegram API.
- Ruff, форматирование и актуальность lock-файла проверены.
- Проверены миграция с нуля, откат, повторное применение, сверка схемы и старт приложения на мигрированной базе.
- Проверены резервное копирование активной WAL и восстановление снимка.
- Docker Compose v2.39.4 принял конфигурацию. В рабочем окружении отсутствует Docker Engine, поэтому сборка образа и запуск контейнера здесь не проверялись.
- Песочница не доставляла в asyncio уведомления от рабочего потока aiosqlite. Интеграционные проверки выполнены вне песочницы с разрешением пользователя на временных локальных базах.
